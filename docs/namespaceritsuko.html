◆ open_cvls_heap()

H5::DataSet ritsuko::open_cvls_heap ( const H5::Group & handle,
const char * name )
inline

Open a HDF5 dataset containing the compressed VLS heap. This should be a 1-dimensional dataset of unsigned 8-bit integers, representing the concatenation of bytes from all the variable length strings in the compressed VLS array. Ideally, all bytes are referenced by at least one CvlsPointer in the associated pointer dataset, though this is not required, e.g., if a heap entry is replaced with a shorter string.

We use an integer datatype rather than HDF5's own string datatypes to avoid the risk of a naive incorrect interpretation of the heap as an array of fixed-width strings.

To read the heap into memory, we first read the bytes into an uint8_t array via H5::DataSet::read, and then access those bytes via an aliased char *. By comparison, directly reading the bytes into a char array is susceptible to overflow problems if HDF5 needs to convert the file's unsigned integers to a possibly-signed char type. Conversely, to write to the heap, we use an unsigned char * to alias the content of each C-style string (following C++'s strict aliasing rules). We pass this aliasing pointer to H5::DataSet::write, which trivially converts from NATIVE_UCHAR in memory to the file's 8-bit unsigned integer datatype.

Parameters
handleGroup containing the dataset of pointers.
nameName of the dataset of pointers.
Returns
An open handle into a HDF5 dataset.

H5::DataSet ritsuko::open_cvls_pointers ( const H5::Group & handle,
const char * name,
size_t offset_precision,
size_t length_precision )
inline

Open a HDF5 dataset containing pointers into the compressed VLS heap, used to define the individual strings in a compressed VLS array.

There are no restrictions on the ordering of entries in the pointer dataset. Slices for consecutive ClvsPointers do not have to be ordered or contiguous. This allows one or more entries in the CvlsPointer dataset to be modified without invalidating other entries. Different CvlsPointers can even refer to the same or even overlapping slices, which provides some opportunities to improve compression for repeated strings.

An error is raised if the dataset's datatype is not compound or does not meet the expectations defined by validate_cvls_pointer_datatype().

Parameters
handleGroup containing the dataset of pointers.
nameName of the dataset of pointers.
offset_precisionMaximum number of bits in the integer type used for the start offset, see CvlsPointer::offset.
length_precisionMaximum number of bits in the integer type used for the string length, see CvlsPointer::length.
Returns
An open handle into a HDF5 dataset.

◆ validate_cvls_pointer_datatype()

void ritsuko::validate_cvls_pointer_datatype ( const H5::CompType & type,
const int offset_precision,
const int length_precision )
inline

Validate that a compound HDF5 datatype meets the expectations for storage in a CvlsPointer instance, specifically:

  • It has exactly two members.
  • The first member is named offset and is of an integer datatype that is unsigned and has no more than than offset_precision bits.
  • The second member is named length and is of an integer datatype that is unsigned and has no more than than length_precision bits.

The constraints on the precision of each integer type ensure that the pointer dataset can be represented in memory by the associated type. For example, setting offset_precision = 64 allows readers to safely assume that a uint64_t can be used for CvlsPointer::offset.

On success, the contents of the HDF5 dataset associated with type can be safely read into an array of appropriately parameterized CvlsPointer instances. Otherwise, an error is thrown.

Parameters
typeCompound datatype, typically generated from a H5::DataSet instance.
offset_precisionMaximum number of bits in the integer type used for the start position, see CvlsPointer::offset.
length_precisionMaximum number of bits in the integer type used for the string size, see CvlsPointer::length.
